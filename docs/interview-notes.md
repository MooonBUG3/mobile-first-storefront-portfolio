# 面试讲述要点（STAR）与常见问答

## 1. 项目一句话

> "我把一个桌面优先的 Astro 独立站重铸为移动优先版本，做了完整脱敏后开源：
> 16 项移动优先改造、双语切换管线、CI 防回归，并在真实浏览器完成触控与溢出实测。"

## 2. STAR 讲述（2 分钟版）

**S 情境**：原站是桌面优先建站的典型产物——`max-width` 降级适配，
移动端存在横向溢出、触控目标小、CLS 抖动等问题；而目标岗位要求的是
"移动端体验与转化数据能力"。同时原站服务真实诊所，不能直接公开代码。

**T 任务**：交付一个既证明工程能力、又不泄露客户信息的作品集：
移动优先重铸版 + 脱敏 + 公开仓库，同时保留原站的信息架构与视觉延续性。

**A 行动**：
- 断点策略反转（px/`max-width` → em/`min-width`），基线样式写给 360px；
- 渐进增强导航：`data-js` 前置判断，无 JS 时静态导航仍可用；
- 触控与系统适配：44px 目标、`touch-action`、安全区、吸底 CTA；
- 自研 i18n：构建期英文入 HTML 保 SEO，`langchange` 总线同步交互组件，
  `data-pending-lang` 防闪烁；
- 工程化：strict TS、CI 含"dist 产物 ↔ 字典"键完整性校验；
- 验证：headless Chrome 实测 390px 七路由零溢出、全交互元素 ≥44px、
  双语恢复、抽屉开合、1440px 桌面走查。

**R 结果**：零 Lighthouse 严重告警的构建产物；所有检查项通过；
仓库以 MIT 公开，含 6 篇过程文档，可复现（`npm ci && npm run build`）。

## 3. 常见问答准备

**Q：为什么不用 Next.js / Nuxt？**
内容型官网，SEO 与首屏是主要矛盾。Astro static 输出几乎纯 HTML，零框架运行时；
Next.js 也能 SSG，但会为一个静态站引入 React 生态的心智与体积。
选型看问题形态，不是看流行度。

**Q：为什么不用 Tailwind？**
原站是原生 CSS + 设计令牌的架构，作品集目的是展示同源架构的工程能力；
且移动优先重写要求对每个断点的每个声明有完全控制。
另外全站 CSS 约 7KB，含 tree-shaking 后的 Tailwind 也未必更小。

**Q：i18n 为什么不用现成库？**
双语、190 个键、无需复数规则与日期本地化——引入 i18next 或外部服务
是负收益。自研方案的优势是：构建期渲染进 HTML 保 SEO、`langchange` 总线
让交互组件零成本订阅、类型上 `I18nKey` 编译期防拼写错误。
真正的判据：**规模到阈值（多语言复数/日期/第三方 translators）就必须换库。**

**Q：移动优先和桌面优先到底差在哪？**
不是"断点方向反了"这么简单。桌面优先的移动端样式是覆盖层——断了某条查询，
桌面样式就泄漏到小屏；移动优先的桌面样式才是增强层，断点没命中时
页面优雅退回单列。同样一套 HTML，故障模式完全倒置。

**Q：数据是真的吗？可复现吗？**
仓库不含任何真实客户数据（脱敏文档有核验命令）。性能与触控数据是
构建产物 + headless Chrome 实测得出，方法在文档中完全写明，`npm run build` 可复现。
面试现场可以现场构建筑跑 grep。

**Q：GitHub Pages 和原来 Cloudflare Workers 的区别？**
适配器不同，产物同源。Workers 走 `@astrojs/cloudflare`，Pages 直接上传静态产物；
这也说明架构没有和任何平台绑定。

**Q：如果让你接手一个很慢的 WooCommerce 站，你第一天做什么？**
先测量再动刀：CrUX/RUM 看真实用户 LCP 分布，Lighthouse 看首屏阻塞，
Clarity 看高价值路径（商品→购物车→结账）的流失录屏。
九成情况先解决图片格式/尺寸与渲染阻塞的插件，再谈主题重做。
参照 woocommerce-mapping.md §4 的完整循环。

**Q：你在这个项目里最大的技术判断是什么？**
i18n 的"构建期英文 + 客户端中文"双段渲染。纯客户端方案 SEO 受损，
纯构建期方案要多一份中文 HTML 且切换需整页刷新。
两段式让首帧零闪烁、中文零请求、SEO 完整——代价是要处理
`visibility` 隐藏与 `langchange` 订阅，这个复杂度我认为值。

## 4. 讲述雷区（避免）

- ❌ 把演示项目说成"我运维的生产站"——是"基于生产架构的脱敏重铸"；
- ❌ 引用任何具体转化率/收入数字（脱敏仓库没有、也不该编）；
- ❌ 声称"移动端建设置完成度 100%"——文档里写了 og:image 等显式取舍；
- ❌ 只讲 CSS 技巧不讲策略——本案例的卖点是方法论完整闭环，不是某个动画。

## 5. 讲述节奏建议

- **2 分钟版**：上面 STAR，落点在"策略反转 + 验证闭环"；
- **5 分钟版**：加 i18n 双段渲染与 CI 键校验两个技术细节；
- **深挖版**：对应 docs 六篇逐篇可展开，被问哪篇翻哪篇；
- **收尾句**："案例讲的是移动优先这一个点，但流程上诊断—方案—实施—验证—数据
  这五步，就是我对独立站技术运营工作的理解。"
